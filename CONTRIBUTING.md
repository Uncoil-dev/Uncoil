# Contributing

Thanks for helping. Small, focused pull requests are easiest to review.

## Pull requests

- One task per PR, ideally under about 200 changed lines.
- Open it against `main`.
- Code changes need tests. Blog and docs changes must pass `npm run test:content`.
- Run `npm run lint` and `npx tsc --noEmit` before you open it.
- Describe what changed in plain terms.

## AI-assisted contributions

You can use AI tools to write code, tests, or text. The rules are the same as for any contribution:

- You own what you submit. Read and understand every line, and be ready to explain it.
- Run the code and the tests yourself. Do not submit output you have not checked.
- Keep the PR small and on one task.
- Do not paste in generated text you cannot stand behind, such as invented APIs, made-up links, or filler descriptions.

Pull requests that are unreviewed AI output, such as code that does not run, empty or generic descriptions, or changes unrelated to the task, may be closed without a detailed review.

## Security

Report vulnerabilities as described in [SECURITY.md](SECURITY.md), not in public issues.
